# task-management/zeigarnik-recall-refuted-011

Two claims are usually bundled together: that unfinished tasks stay in memory
more strongly than finished ones, and that people tend to go back to unfinished
tasks. The first meta-analysis of both finds that only the second one holds.

On memory: once Zeigarnik's own 1927 data is set aside, interrupted and
completed tasks are recalled at essentially the same rate -- interrupted tasks
make up 49.16% of what is recalled, against a 50% null, and the pooled effect
size is negligible. The founder's own study noticeably moves the pooled
estimate, which is a familiar shape for a historically famous effect.

On resumption: interrupted tasks are picked up again about 67% of the time,
well above chance, and the result barely changes when the founding study is
removed.

So the mechanism story that gets built on top of this -- open loops occupying
memory, creating tension, demanding closure -- does not have the memory finding
underneath it any more. What is left is a behavioural tendency: people do come
back to things they started.

For a task system that changes what is worth doing. Capturing an item is not
worth defending on the grounds that it "frees up mental space", because the
memory advantage it was supposed to free up does not replicate. Capture is
worth defending on the plainer grounds that an unrecorded item is invisible to
the system. And the resumption finding sets an expectation for the log: started
work usually gets touched again, so a started item that is never touched again
is genuinely unusual and worth surfacing -- as a question, under the rule in
task-management/record-is-not-behaviour-009.

The authors' own caution is worth carrying: they suggest the memory effect may
depend on conditions -- an authoritative experimenter, strong task involvement
-- that were common in the historical studies and are rare now. That is a
hypothesis about why it fails, not a rescue of it.

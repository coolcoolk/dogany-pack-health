# progress-tables.md

이 문서는 표(0) 매트프렙 드릴 진척도표, 표(0-E) 기구프렙 드릴 진척도표, 표(1) 세션 시작 전체 루틴 카드, 표(3) 종목전환 개요표, 표(4) 세션 종료 카드 렌더 시, 트렌드 블록, 유효볼륨 0.5, final-lock 체인지로그 확인 시 읽는다.

**세션 표 공통 (owner 2026-10-02).** (1) 마커는 한 벌이다 -- 세트표 방식 ASCII `[v]` 완료 / `[>]` 진행중(종료 카드에서는 덜 하고 끝남) / `[ ]` 예정 (owner 2026-10-02 10:12·11:06로 `[-]` 은퇴). 표(0)·(0-E)·(3)·(4) 전부 `service/health/card_lib.py` 의 `MARK_DONE` / `MARK_CURRENT` / `MARK_PENDING` 을 쓴다. `[>]` 는 한 카드에 **최대 한 줄** -- 지금 들어가 있는 종목뿐이다(owner 2026-10-02 09:15). (2) 세션 표의 근육 이름은 해부 짧은 표기(2026-08-21 락: 둔근 / 햄스 / 사두 / 이두 / 삼두 / 등 / 어깨 / 가슴 / 종아리 / 복근 = `muscle_label` form='short')다. `ui_labels.MUSCLE_PLAIN_KO`(엉덩이 / 팔 앞쪽)는 **프로그램 카드(program-plan) 전용**이고 세션 표에 오지 않는다. (3) 표(0)·(0-E)·(3)·(4)는 전부 코드가 그린다. 모델이 손으로 그리는 세션 표는 없다.
표(2) 세트 진척도표는 set-table이 렌더하고 **코드가 보낸다** -- 렌더도 발행도 코드 (service/health/set-table + exercise-enter). 모델이 중계할 것은 없다: 발행에 성공하면 stdout 에 표가 아니라 영수증(`SET_TABLE delivered=yes by=code`)만 남는다. 전송이 **실패했을 때만** 코드가 stdout 으로 행을 되돌려주고(`SET_TABLE fallback=defenced`), 그때는 그 행들을 그대로 중계한다. 표를 손으로 타이핑하는 일은 어느 경우에도 없다.

**발행 주체 (2026-09-11 결정).** 표(2)는 **세트가 기록될 때마다** 나간다. 사용자 축자: 「제발 세트마다 표를 내자는 의미잖아」. 운반은 세 조각이고 전부 코드다.

- `set-add` 가 DB 커밋 직후 `exercise-enter --publish-table` 를 부른다 -- 표3 핀 갱신(`--refresh-card`)과 같은 자리, 같은 best-effort 모양. 기록을 잃는 실패는 없다.
- `do_publish_table` 이 현재 상태로 다시 렌더하고 **F14 프렙 게이트를 그대로 통과시킨다.** 진입 프렙이 남아 있으면 그 세트는 표를 내지 않고 `SET_TABLE held=prep_incomplete` 만 남긴다. 밴드를 닫는 드릴이 그 종목의 첫 표를 낸다.
- `deliver_set_table` 이 **표 내용 1건당 배달 1건**을 set-arm 의 배달 원장(`step_affordance`)에 선점한 뒤 보낸다. 종목 진입 발행과 세트 발행이 같은 순간에 겹쳐도 화면에는 한 장만 나간다.

이건 세트마다 나가는 **새 메시지**다. 인플레이스 편집이 아니다 -- 사용자 지침(2026-08-21 「같은 메시지 인플레이스 스왑」)을 어기는 게 아니라, 표(2)에는 인플레이스 경로가 **없기 때문**이다. 편집 가능한 표면은 브릿지가 붙잡고 있는 핀 메시지 하나뿐이고 그건 표(3)이 쓰고 있다. 표(2)를 거기 얹으면 인라인이 아니게 되고 길이 예산에서 표(3)을 밀어낸다. 발신 경로(`routines/push.sh`)는 sendMessage/sendPhoto 뿐이라 편집 API 자체가 없다.

**서버 푸시 훅은 없다 (H6 정정, 2026-08-24. 위 결정으로 대체됨 -- 아래는 왜 그 자리가 비어 있었는지의 기록이다).** 이 자리에는 「전달은 서버 푸시 훅(routines/set-table-followup.py)이 담당한다」고 적혀 있었다. 사실이 아니었다. 그 파일은 존재하지만 (1) 사용자에게 아무것도 보내지 않고 `hookSpecificOutput.additionalContext`로 **모델에게 지시를 내리는** 훅이며, (2) `.claude/settings.json` 어디에도 등록돼 있지 않다(실측 `grep -c` -> 0). **한 번도 돈 적이 없다.** 이 문서가 "표는 이미 사용자 화면에 도착해 있다"고 말했고 모델은 그 지시를 정확히 지켰고 표는 안 갔다. 그리고 모델은 그 빈자리를 **자기 실수로 서술했다.** 없는 기구를 있다고 적은 문서가 만든 자백이다. 등록 여부는 별도 결정 사안이고, 이 문서는 **지금 도는 것만** 적는다.

## (0) 매트 프렙 드릴 진척도표 (F1, 2026-08-10)

매트 프렙(0단계) 진입 시, 그 세션의 매트프렙 드릴 체크리스트를 전체 한 번에 코드블록 표로 노출 -- `[v]`(완료)/`[ ]`(예정).

**코드가 그린다 (2026-10-02).** 렌더 = `card_lib.render_prep_table`, 데이터 = `exercise-enter` `prep_table_rows`. 발행은 두 곳이고 둘 다 코드다:
- 매트프렙을 호스트하는 종목의 진입(`exercise-enter`) -- 드릴이 남아 있을 때, PREP_ENTRY 줄들 **앞에**.
- 매트 드릴 한 개가 기록될 때마다 `set-add` 가 `exercise-enter --prep-table mat` 을 불러 갱신본을 SET_LOGGED 뒤에 싣는다. 마지막 드릴이 닫히는 순간 전부 `[v]` 인 표가 한 번 나간다.

stdout 모양: `PREP_TABLE kind=mat done=n/N` 머리 줄 + 펜스(```)까지 붙은 표. 머리 줄은 떼고 펜스 블록을 **그대로** 중계한다(stdout-tokens.md). 표를 다시 타이핑하거나 고치지 않는다.

**드릴 카드가 표를 싣는다 (owner 2026-10-12 06:27 「순서가 엉망인데」).** 코드 레일(`PREP_TAP_POSTED` / `PREP_CARD` / `SET_BLOCKS ... table=card`)에서는 다음 드릴 카드 한 메시지가 위에서부터 **표 → 드릴(이름·용량, 단계, 주의) → `✅ 완료` 버튼** 순서로 나간다(set-arm `post_prep_tap`). 그때 stdout 의 `PREP_TABLE` 펜스와 `SET_CUE` 블록은 그 카드가 이미 보여 준 내용이다 -- 중계하지 않는다(중계하면 카드 뒤에 표가 따로 붙고 드릴이 두 번 나간다). 이 표는 `PREP_CARD` / `table=card` 줄이 없을 때(코드 레일 꺼짐·전송 실패)에만 중계한다.

- 출처 = prep.yaml 의 그날 세션 단위 매트프렙(`live_slot` 없음 + `phase: mat_prep`, `set-table.session_prep_drills`) -- 핀 카드의 `준비운동` 행과 set-add 의 다음 드릴 안내가 세는 바로 그 목록. 완료 = 세션 단위 프렙 행(slot NULL)의 `prep_seq(i)`.
- prep.yaml 에 세션 단위 매트프렙이 **없으면** 이 표는 나가지 않는다. 빈 표도, 추정 목록도 만들지 않는다. (구판은 출처를 stretch-matrix.md 프로즈로 적었다 -- 그 파일은 새 인스턴스에 없고, 라이브 프렙의 SoT 는 prep.yaml 이다.)
- (1) 세션시작 전체루틴표의 `0 매트 준비운동` 개요 행(조망용 한 줄)과는 다른 층위 -- 이건 매트프렙 실행 동안 상태를 추적하는 전용 진척도 표면.
- 표 끝에 빈 줄 하나 + 세트표와 같은 이전/다음 줄: 매트 준비운동은 `▸ <첫 종목>`, 종목 준비운동은 `◂ <앞 종목>` / `▸ <그 종목>` (owner 2026-10-02 11:21 「이전/다음 종목도 보여줬으면해 세트 진행표랑 비슷하게」).
- 각 줄 끝에 처방 용량을 붙인다: `<동작> · 10회` / `좌우 8회` / `15초 x 2` / `30초` -- prep.yaml 의 target_reps·target_unit·hold_sec 그대로(`prep_target_spec` → `card_lib.prep_dose_text`), 처방이 없으면 이름만 (owner 2026-10-02 11:13 「반복수 이런것도 써주라」).
- 포맷 (owner 2026-10-02): 머리 줄 `🧘 매트 준비운동 · <완료>/<전체> 완료` (owner 2026-10-12: 숫자만으로는 "완료 수"인지 "지금 몇 번째"인지 안 읽혀서 `완료` 를 붙인다), **빈 줄 하나**, 그다음 드릴마다 `[v]`/`[ ]` + 드릴명 한 줄.

예시 (실제 렌더, 픽스처 DB):
```
🧘 매트 준비운동 · 2/4 완료

[v] 발목 도르시플렉션 · 좌우 10회
[v] 무릎 스크루홈 · 10회
[ ] 밴드 니-아웃 · 15회
[ ] 다이나믹 내전근 활성화 · 좌우 8회
```

## (0-E) 기구 프렙 드릴 진척도표 (H3, 2026-08-24)

**표(0)의 정확한 미러다.** 매트 프렙에는 개요 표면이 있고 기구 프렙에는 없었다 --
비대칭 자체가 결함이었다. 아침 카드는 두 블록을 대칭으로 렌더하는데(`0 매트 준비운동` /
`E 장비 준비운동` / 슬롯별 `W` 행) 라이브 표면만 한쪽이 비어 있었다.

슬롯 진입 시, 그 슬롯에 걸린 기구프렙 드릴 체크리스트를 **전체 한 번에** 코드블록
표로 노출한다 -- 표(0)와 같은 `[v]`(완료)/`[ ]`(예정) 마커.
- **코드가 그린다 (2026-10-02).** 진입 시 `exercise-enter` 가 PREP_ENTRY 줄들 앞에 싣고,
  기구프렙 드릴이 하나 기록될 때마다 `set-add` 가 `exercise-enter --prep-table equipment`
  갱신본을 싣는다. stdout 모양은 표(0)와 같다(`PREP_TABLE kind=equipment done=n/N` + 펜스
  블록) -- 머리 줄은 떼고 블록을 그대로 중계한다.
- **출처 = 그 슬롯의 진입 프렙 계획(`PREP_ENTRY` 행들과 같은 목록), 선언 순서 그대로,**
  거기서 `mat_prep` 드릴(표(0) 몫)을 뺀 것. `display=` 값 그대로. 완료 = 그 종목의
  프렙 행이 그 드릴의 `prep_seq` 에 있는지. stretch-matrix.md를 뒤져 드릴을 지어내는 것은
  금지 -- 진입 프렙이 0행이면 그 슬롯엔 기구프렙이 없는 것이고, 표를 내지 않는다.
- 포맷 (owner 2026-10-02): 머리 줄 `🔧 <종목명> 준비운동 · <완료>/<전체> 완료` (owner 2026-10-02 11:10; 종목명을 모르면 `장비 준비운동`)
  (종목명 = program.yaml display 에서 끝 괄호를 뗀 것), **빈 줄 하나**, 드릴 행들.
- 위치: **프렙 순차 전달을 시작하기 전.** 이 표는 "이제 이것들을 하나씩 할 겁니다"라는
  조망이고, 표(2) 종목 진입 표보다 앞선다(F14 -- 프렙이 종목 표/큐보다 먼저 gate-close).
- 개요가 순차 안내를 **대체하지 않는다** -- 표(0)와 같은 조항. 드릴은 여전히 하나씩
  순차로 안내하고 완료 버튼을 받는다. 표는 조망용 상태 표면일 뿐이다.
- `PREP_IMMEDIATE`(즉시 프라이머) 행은 이 표에 **넣지 않는다.** 그건 워킹세트 1 직전에
  발화하는 별도 단계이고, 진입 시점 조망에 섞으면 "지금 할 것"으로 오독된다.

왜 이 표가 필요한지는 사용자 말로 이미 찍혀 있다: 기구프렙이 프로즈로만 흘러가던 날,
다음에 뭐가 오는지 안 보여서 사용자가 물으셨고 모델은 "빼먹은 거 아니에요"를 변명해야 했다.
개요 표가 없어서 치른 비용이다.

예시 (실제 렌더, 픽스처 DB -- 바벨 로우 슬롯 진입 프렙 3행 중 2행 완료):
```
🔧 바벨 로우 준비운동 · 2/3 완료

[v] 밴드 풀어파트
[v] 스캡 풀업
[ ] 가벼운 로우 (빈 봉 10회)
```

데이터 전제 (H3의 하중을 지는 절반): 이 표는 `PREP_ENTRY` 행 없이는 그릴 수 없다.
2026-08-24 이전엔 슬롯 결속 기구프렙이 `card_slot`만 갖고 `live_slot`이 없어서 라이브에
**한 행도 안 나갔다** -- 아침 카드엔 있고 라이브엔 없었다. `prep.yaml`이 18개 드릴에
`live_slot`을 부여해 그 구멍을 닫았다. 표가 비어 보이면 사양이 아니라 **데이터를 먼저
의심할 것**: `exercise-enter <sid> <exercise>` stdout의 `PREP_ENTRY` 행 수를 세 보면 된다.

## (1) 세션 시작 전체 루틴 카드 (owner-confirmed 2026-07-18, 포맷 카드형 재조정 2026-07-29)

오늘 전체 루틴 표(전체 슬롯)를 0단계 동적 스트레칭 안내와 함께 세션 시작 시 한 번 보여줄 것. (2)/(3)과 별개 -- 세션 시작 1회.

포맷 (owner-confirmed 2026-07-29): 정렬 그리드가 아니라 종목당 카드 2줄 구성. 헤더 행("SLOT/종목" 등) 없음. 종목 사이 빈 줄 없이 연속 배치. 코드블록 유지.
- 1행: `<슬롯번호> <program.yaml display 필드 한글 종목명>`
- 2행: 3칸 들여쓰기 + `└ ` (박스 드로잉 문자, U+2514) + 상세 `<n>세트  <무게>kg  <하한>-<상한>회` (세트/무게/반복 사이 공백 2칸). 무게 미확정(첫세션 캘리브레이션, program.yaml weight_kg null)이면 `<무게>kg` 토큰 자체 생략, 반복 토큰 뒤에 `  (첫 세션)` 부착.
- 마커는 반드시 `└` (ASCII 인접 박스 드로잉 문자) 사용, 한글 자모 `ㄴ` 금지 (폰트/로케일에 따라 폭이 달라짐, `└`는 모노스페이스 환경에서 폭 1 고정).

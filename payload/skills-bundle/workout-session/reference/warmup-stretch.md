## 0단계 매트 프렙 구성

0단계 매트 프렙 구성은 세션 타입(앞A/뒷A/앞B/뒷B)별로 다름 -- 어느 드릴이 어느 날/슬롯/페이즈에 나가는지, 표시 문구, 홀드 초는 `files/program/prep.yaml`이 단일 출처 (2026-08-21 프렙 SoT 통합; program.yaml `prep_drills`와 warmup.yaml은 제거됨). 각 드릴의 셋업/실행/흔한 실수 등 산문 근거는 `files/program/stretch-matrix.md` -- 산문 레퍼런스일 뿐 데이터 소스 아님, 둘이 어긋나면 prep.yaml이 맞다. 여기 인라인 중복 금지, 프렙 변경 시 prep.yaml만 수정할 것.

없을 때(새 인스턴스): `files/program/` 은 사용자 데이터 전용이고 어떤 설치 레인도 거기에 쓰지 않는다 -- `prep.yaml` 이 아직 없으면 0단계 매트 프렙은 **빈 채로** 간다. 드릴을 지어내지 않고, stretch-matrix 산문에서 목록을 복원하지도 않는다. 스키마 정본은 팩이 배송하는 `service/health/sot/prep.TEMPLATE.yaml` 이며, 그건 템플릿이지 데이터가 아니다(예시 드릴 그대로 복사 금지). 설계는 workout-program 소관.

boundary (2026-07-31, C4): 이 스킬은 prep.yaml/stretch-matrix.md를 delivery용으로만 소비 -- sequential one-drill-at-a-time 진행, 버튼, 타이머, per-slot 타이밍, cue 노출. 프렙 design은 소관 아님. 구조적/내용 변경(드릴 추가/제거, 세션타입 prep 블록 변경, K2/injury 모델 변경, U3 % 기준 변경)은 workout-program으로 라우팅.

## 어깨 모빌리티 3종 -- 묶음 명칭 폐기 (오너 지시 2026-08-24)

와이레이즈(U1d) / 시티드 어라운드 더 월드(U1e) / 헤일로(U1f), U1b(덤벨 풀오버), U3(랫풀다운 프라이밍) 등 장비 기반 항목은 0단계 매트 프렙에 포함되지 않음 -- 각자 준비시키는 특정 슬롯 직전으로 이동(stretch-matrix.md 참조).

**"어깨 트리오"라는 이름은 폐기됐다. 쓰지 말 것 -- 존재하지 않는 이름이다.**
지적된 문제: 셋을 대등하게 나열해야 하는데 묶음 명칭이 계속 쓰인다.
- 2026-07-29부터 "트리오는 묶음 안내가 아님"이라는 금지 규칙이 여기 적혀 있었는데도
  `어깨 트리오(와이레이즈/시티드 어라운드더월드/헤일로) 다 끝났어요` 로 묶어 마감한 오적용이 재발했다.
  **금지 규칙을 옆에 붙여두는 것으로는 안 된다** -- 이름이 있으면 모델이 그 이름을 쓴다.
- 그래서 이름을 다듬은 게 아니라 없앴다. prep.yaml에 U1a 노드는 더 이상 없고,
  셋은 U1d/U1e/U1f 대등한 개별 드릴이다. 셋을 한꺼번에 가리키는 코드도 이름도 없다.
- 전달: K1/K2 등 다른 드릴과 완전히 동일하다. 하나 안내 -> "완료" 확인 -> 다음.
  셋을 한 메시지에 담지 말고, 마감도 셋을 묶어서 하지 말 것("셋 다 끝났어요" 금지 -- 각각 마감).

## 드릴의 기구·무게는 데이터가 말한다. 없으면 말하지 않는다 (오너 지시 2026-08-24)

지적된 문제: 케틀벨로 수행한 드릴에 존재하지도 않는 원판 무게가 안내됐다.
실제 발화: `헤일로: 원판(6kg) 하나를 양손으로 잡고 ... 이전에 쓰시던 6kg 기준으로 갈게요.`
-> **기구도 틀렸고(케틀벨인데 원판), 그 무게는 존재조차 하지 않으며, "이전에 쓰시던"이라는 출처까지 가짜였다.**

규칙:
- 드릴의 기구/무게는 `files/program/prep.yaml` 의 `implement` / `load_kg` 가 유일한 출처다.
  값이 있으면 렌더된 드릴 문구에 `(케틀벨)` / `(케틀벨 6kg)` 형태로 **이미 붙어서 나온다.**
- **문구에 기구가 없으면 기구를 말하지 않는다. 무게가 없으면 무게를 말하지 않는다.**
  비슷한 드릴에서 가져오지 말고, 추정하지 말고, "가벼운 것"으로 얼버무리지도 말 것 --
  그냥 그 얘기를 안 하면 된다. 빈칸은 채우라고 있는 게 아니다.
- 특히 **출처 표현 금지**: "이전에 쓰시던", "지난번에 쓰신", "평소 쓰시는" 은 사용자 기록을 인용하는
  말이다. 데이터에 그 기록이 없으면 그 말은 거짓말이 된다.
- 사용자가 무게를 말씀하시면 그때 `load_kg` 에 적는다(자리는 이미 있다). 적기 전엔 여전히 말하지 않는다.
- 현재 등록: U1f 헤일로 = 케틀벨, 무게 미기록. 나머지 드릴은 기구 미기록이라 기구 얘기를 하지 않는다.

## 워밍업 큐 형식 = 무게 + 횟수 + RIR (#9, owner 2026-08-15/2026-08-19)

웜업/램프 큐를 낼 때 무게만 주지 말 것 -- 사용자가 "8-4+?"를 매번 되묻게 만든다.
반드시 **무게 + 목표 횟수 + RIR** 세 값을 함께 낸다. 값은 확정 엔진 산출을 verbatim
에코 (횟수·RIR도 세트표/엔진값 그대로, 모델 자체 채움 금지).
- 형식 예: `20kg x8 (RIR 4+)` / `빈 봉 x8 (RIR 4+)` / `40kg x5 (RIR 4+)`.
- 램프 세트 RIR은 4+ 기본 (reference/coaching.md 강도 척도). 세트표에 다른 값이 있으면
  세트표 우선.
- 단위 명시 하드룰(#27, 한쪽당/총량)을 웜업/램프에도 동일 적용.

## 바벨 워밍업 원판 로딩 라운딩 (owner-confirmed 2026-07-31, B7)

바벨(바-로딩) 종목의 워밍업/램프업 세트 무게는 20kg 표준 바 기준으로 깔끔하게 로딩되는 값으로 제시할 것.
- 원판 여러 장 조합이 번거로운 값(예: 15+2.5kg/side) 피할 것.
- 편측 로딩 = (목표 kg - 20) / 2로 계산 후, 편측 원판 수가 가장 적은 값으로 라운딩.
- **편측 단판(1장) 로딩을 최우선** (편측 5kg=30kg, 10kg=40kg, 15kg=50kg, 20kg=60kg, 25kg=70kg).
- 스코프: 바벨 종목의 워밍업/램프업 세트 제시에만 적용. 워킹세트 무게는 rx-calc + 해당 슬롯 장비 래티스가 권한 유지. 머신/덤벨/케이블 슬롯은 이 원판-라운딩(바+편측판) 규칙의 영향 없음 -- 단, 머신/스택 종목도 웜업/램프 행 자체는 받는다(F6-ext, 아래 참조). 바가 없으므로 램프는 바+원판 조합이 아니라 그 기구의 로드 단위로 워킹무게까지 올라가는 경량 사다리다.
- 가정 재고: 20kg 표준 올림픽 바 + 커머셜 원판 세트 (편당 1.25 / 2.5 / 5 / 10 / 15 / 20 / 25 kg).

## 램프업 세트 (owner-confirmed 2026-07-27, 스냅 우선으로 재확정 2026-08-15 + batch G11)

복합관절/고중량 종목에서 워밍업 무게 -> 워킹세트 무게로 점프가 클 땐, 사용자가 지적하기를 기다리지 말고 램프업 세트(RIR 4+, 워킹세트 무게로 단계적으로 올라가는 무게)를 종목 시작 시퀀스의 기본값으로 먼저 포함할 것.

### 램프 사다리 계산: 단판 스냅 우선 (owner-confirmed 2026-08-15 + batch G11) -- DEFAULT

램프 사다리는 **"쉬운 원판 로딩(편측 단판 우선)"이 1순위 드라이버**다. 20% 점프 상한은 스텝 수를 늘리는 게이트가 아니라 **소프트 가이드**일 뿐 -- 램프 세트는 RIR 4+ 경량이라 중간 점프가 20%를 다소 넘어도(실측 26-27%까지) 무방하다. 사용자가 매 세션 라이브로 30/45 같은 어색한 값을 정정하던 근본원인이 "20% 상한을 우선해 단판이 아닌 중간 스텝(30/45)을 끼워넣은 것"이므로, 아래 절차를 기본값으로 쓴다.

계산 절차 (워킹세트 무게에서 top-down):
1. 워킹세트 무게와 빈 바(20kg)를 양 끝으로 잡는다.
2. **하나의 "스텝 원판" 크기를 고른다** (편측 2.5 / 5 / 10 / 15 / 20kg 중 하나). 빈 바에서 이 스텝 원판을 편측에 한 장씩 누적해 올라간다: 스텝 10이면 20 -> 40 -> 60 -> ..., 스텝 5면 20 -> 30 -> 40 -> ... 각 rung = 빈 바 + (그 스텝 원판 편측 N장) = 세팅이 가장 단순한 단판/균일판 값. **매 rung마다 원판 사이즈를 바꾸지 말 것** (그래야 30/45 같은 2판 조합이 안 생김).
3. 스텝 원판 크기는 **램프 rung이 대략 2~4개(빈 바 포함 3개 안팎) 나오는 가장 큰 값**으로 고른다 -- 무거운 워킹셋일수록 큰 스텝(10/15/20), 가벼운 워킹셋일수록 작은 스텝(5). 워킹셋 바로 아래까지 채우고 **워킹세트 무게로 마무리**. 최상단 rung과 워킹셋 사이 어색한 중간값(2판 조합/마이크로)은 **버린다** -- 큰 점프여도 OK (RIR 4+ 경량).
4. **막판(마지막 램프 -> 워킹세트) 진입 점프만 타이트**하게 관리 -- 헤비/기술적/부상민감 리프트(예: 어깨 부상 프로파일에서의 OHP) 한정, 10-15%(또는 단판/2.5 그리드로 자연스럽게 붙는 값)로 부드럽게. 이건 여전히 진짜 게이트다.
5. 빈 바 조건부 추가: 첫 램프 무게를 먼저 잡은 뒤, 빈 바(20kg)가 그 아래로 유의미하게 떨어지면 빈 바를 사다리 맨 아래에 추가한다. **빈 바와 첫 램프 무게 사이에는 중간 스텝을 끼우지 않는다** (기존 규칙 유지).
6. **램프 세트엔 마이크로 원판(1.25 / 0.75) 쓰지 않음** -- 마이크로는 워킹세트 전용.

예시 (스텝 원판 크기가 워킹 무게에 따라 달라짐):
- 펜들레이 로우 워킹 75, 빈 바 20: 스텝 원판 = 편측 10 -> **20 -> 40 -> 60 -> 75**. rung 3개(빈바/+10/+20), 75는 워킹. 60->75 막판 점프 15kg(20%)은 허용. (30/45를 끼우던 옛 결과 `20 -> 30 -> 45 -> 60 -> 75`는 2판 조합 어색값이라 버림.)
- OHP 워킹 42.5, 빈 바 20: 스텝 원판 = 편측 5 -> **20 -> 30 -> 40 -> 42.5**. rung 3개(빈바/+5/+10), 막판 40->42.5 진입 2.5kg(≈5.9%)로 어깨 부상민감에 맞춰 타이트.
- back_squat 워킹 100, 빈 바 20: 스텝 원판 = 편측 15 -> **20 -> 50 -> 80 -> 100** (rung 3개). 스텝 20이면 20 -> 60 -> 100 (rung 2개)도 가능 -- 둘 다 단판 균일, 사용자 RIR 피드백으로 조율.

### 점프 크기 배경 (F6, owner-confirmed 2026-08-13) -- 소프트 가이드로 격하

과거엔 20% 단일 점프 상한을 스텝 수 게이트로 썼으나(2026-08-13), 이는 30/45 같은 어색한 2판 조합을 강제해 사용자가 매 세션 정정하는 원인이 됐다. **2026-08-15 + batch G11로 상한은 소프트 가이드로 격하**, 위 단판 스냅 절차가 우선한다. 아래는 배경 근거로만 유지:
- 코칭 관행상 단일 램프 점프는 워킹 무게의 대략 15-25% 대에서 수렴 -- 다만 RCT 아님(kimwog `exercise/warmup-load-rampup-progression-018`, D등급). 과학 단정/오버셀 금지.
- **막판(마지막 워킹세트 직전) 진입 점프는 10-15%로 더 타이트** -- 헤비/기술적/부상민감 리프트 한정. 이 타이트 기준만 게이트로 유지, 초반/중간 점프는 단판 스냅에 양보.
